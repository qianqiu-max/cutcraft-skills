# 在剪辑软件中完成文字漂浮

本参考用于已有剪辑软件、可操作其界面或 API 的 Agent。先确认实际功能，再选择原生文字动画或导入透明文字层。无需同一种 Agent、固定 MCP 或固定软件版本。

以下提供各编辑器中的分层操作思路。请在实际软件版本检查抠像、跟踪、字体和编码支持，以及透明字层导入后的效果。

## 开始前的能力检查

| 检查 | 满足时 | 不满足时 |
| --- | --- | --- |
| 能读取项目、素材和时间线 | 先记录分辨率、帧率、源时间范围、音轨、当前版本，再新建副本 | 从用户给定文件建立新工程，不覆盖原文件 |
| 支持文字位置关键帧和分层 | 可直接制作原生文字层 | 用本 Skill 脚本生成透明文字动画后导入 |
| 支持透明 ProRes 4444 MOV | 导入后用棋盘或彩色底确认透明通道 | 改用支持的 RGBA PNG 序列或其他经实测保留 alpha 的格式，不靠黑色背景冒充透明 |
| 支持人物抠像或轮廓遮罩 | 建立与源片同步的前景层 | 用外部遮罩/透明前景；静态图可手绘轮廓，动态视频需要时变遮罩 |
| 支持动态跟踪且结果可修正 | 跟踪人物与道具，检查丢失和漂移 | 对短片逐帧或分段修正；无法达到遮挡要求时明确未完成 |
| 能保存可编辑工程和导出 | 保存工程、收集引用素材，另存成片 | 至少保存素材、动画参数与操作状态，不声称已交付原生工程 |

优先选当前可用的原生接口、插件或桌面控制工具。根据实际软件版本读取界面，在每次关键操作后核对图层和预览。

## 通用时间线与制作顺序

从上到下建立三类图层：

| 层级 | 内容 | 必须保持的关系 |
| --- | --- | --- |
| 最上层 | 同一源片的主体抠像副本，保留人物及需保护的伞、头发、衣袖、衣摆、手持物 | 与背景使用同一源入点、时间、速度、裁切、缩放及位置；保留原始人物像素 |
| 中间层 | 若干白色、金色文字层，或一个已包含这些字层的透明动画 | 文字及其发光都位于主体之后 |
| 最底层 | 完整原始图片或视频 | 保留原背景，不挖空人物区域 |

1. 设置画幅与帧率，导入素材，确定本次源范围。图片可设为整段时长；视频不要在没有要求时随意变速、循环或补帧。
2. 复制背景建立顶部主体层，完成抠像后检查全部轮廓。动态视频采用逐帧分割、跟踪并修正的遮罩，或已对齐的透明前景；单张静态遮罩不能覆盖移动人物。
3. 建立中间文字层并制作持续向右运动，先验证方向，再调整字体、密度、光效和速度。
4. 锁定背景与主体的同步关系。若要推近镜头，可先把三类层合成嵌套/复合片段，再对整体做同一缩放；也可对背景与主体使用数值完全相同的变换。
5. 检查人物经过文字时，遮挡来自人物真实轮廓，而非中央矩形空洞。必要时适度向外扩展遮罩并轻微羽化；不要让人物内部变半透明。
6. 保存原生工程再导出新文件。原视频的音频只保留一份，关闭顶部复制层的重复声音，避免叠音。

源片剪切、速度变化、倒放、稳定、重定时或重新构图后，必须重新确认主体层及遮罩时序；不能只修改背景层。多个镜头分别处理遮罩，在切点同时切换背景和对应前景。

## 原生文字动画参数

以下是本示例的起点，不是所有素材的硬性尺寸。设输出高度为 `H`，像素参数乘以 `H / 1080`；短竖屏应减少同时可见列数并留意字流密度。

| 层次 | 字体大小起点 | 向右速度起点 | 外观 |
| --- | --- | --- | --- |
| 远处小字 | 38–44 px | 85 px/s | 暖白，较淡、轻微模糊 |
| 中间白字 | 55–62 px | 165 px/s | 白色或米白，主要笔画清晰 |
| 较近金字 | 94–106 px | 275 px/s | 金色光晕、较亮笔画；避免整列过曝成团 |

- 中文采用竖排文本；没有竖排功能时，每个汉字换一行，并检查行距。保留句子顺序，避免添加占位乱码。字体以当前环境可用且适合用途的字体为准，不默认为华文行楷在所有设备可用。
- 每列设置不同横向起点和纵向偏移。可用 12–24 列作为横屏起点，再按画幅和素材调整；较大的字与较小的字具有速度差。
- **横向位置使用线性插值。** 计算 `x(t) = x0 + v × t`，其中 `v > 0`。例如 1080 高画面中，一列金字在 2 秒内向右移动约 550 像素。只左右轻微摆动，或只做上下移动，都不能代替这种流动。
- 字列从左侧画外进入、从右侧完全离开。需要循环时，等整列及光晕完全出画后再从左侧进入，或复制片段接续；不能在画内从右边突然跳回左边。
- 同一速度组适当等距分布；不同组错开相位，避免所有大字挤在同一条竖线上。上下漂移只作很小的辅助运动。
- 原生发光不可用时，可复制字层并添加柔化作为下方光晕，清晰笔画放在其上。两份字层使用完全相同的位置动画，且均在主体层之下。
- “泡泡变焦”是参考教程的可选处理，不是此效果的必要条件。若添加散焦、发光或变焦模糊，应放在主体覆盖之前，或只作用于文字合成；在最终主体合成之后再全局扩散模糊，会把邻近的文字光晕涂进人物边缘。

## 剪映 / CapCut

1. 在当前界面确认是否有多轨、文本关键帧、自动/自定义抠像和遮罩功能；功能名称和可用范围因版本、平台和账户而异，不默认为免费或已解锁，也不主动购买。
2. 以完整素材作为背景；将同一素材复制到上方覆盖轨，对复制层进行人物抠像。默认“人物”识别可能漏掉伞与道具，必须查看这些部分，必要时用自定义抠像或另一个道具保护层补齐。
3. 在背景和抠像层之间建立文字。若使用原生文字，对每列添加起点与终点的位置关键帧，选择线性运动；按上表复制出不同大小、速度与偏移的列。也可在此层导入脚本产生的透明 MOV。
4. 若导入 MOV 出现黑底，先检查文件 alpha 与软件导入能力，不要直接把黑底成片当透明层。原生文字通常比对黑底做“滤色”更可靠；滤色不等同于真实 alpha。
5. 在预览中检查文字经过人物、伞边、衣摆时的遮挡。保存草稿/工程并记录引用素材目录；按该版本可用方式收集工程，不假称存在某个通用导出工程按钮。

## Premiere Pro；必要时结合 After Effects

### 仅 Premiere

- 使用 `V1 背景 → V2… 动态文字或透明 MOV → 更高轨主体副本` 的轨道关系。字幕轨不适合作为这类自由空间字流的默认实现，优先图形文字或透明素材。
- 使用图形层/效果控件中实际可用的位置参数建立线性关键帧。通过轨道或嵌套序列管理近、中、远文字层，避免把所有层合并成同一速度。
- 主体副本可用不透明度轮廓遮罩与可用的跟踪功能。复杂头发、衣摆以及长时移动人物需要精修；不要把某一版本的对象选择/自动抠像视为所有 Premiere 均具备。
- 原生遮罩不足时导入事先生成的透明前景，或在 AE 处理后送回 Premiere。若导入透明 MOV 有暗边/亮边，检查素材的 alpha 解释和预乘方式，不能通过任意放大遮罩掩盖导入错误。

### 可用 After Effects 时

- 背景层复制一份到顶部，用当前可用的 Roto Brush / 轮廓遮罩处理主体，传播到所需时间范围并逐段修正；该工具不保证自动保留伞等非人体物件，可另建遮罩。
- 文字放在中间预合成中，逐列设置位置关键帧、发光及远近虚实。若用表达式驱动水平位置，运动速度的单位应与合成帧率和秒数一致；不要使位置按帧数直接乘以像素每秒。
- 顶部主体层与背景共享相同时间重映射和变换。保存 AE 工程；若不使用动态链接，则输出带 alpha 的前景或完整合成，再导回 Premiere。

## DaVinci Resolve / Fusion

### Edit 页面多轨方式

- 同样采用底部完整背景、中间透明字层、顶部透明主体的三层关系。
- 可用的主体分割功能可能依赖 Studio 版本；先核实，再选择该版本提供的追踪遮罩，或导入外部生成的 alpha 前景。不要假设所有安装都有 Magic Mask。

### Fusion 合成方式

- 将源画面接到第一个 Merge 的背景输入，文字动画接其前景输入，得到“背景＋文字”。
- 将这个结果接到第二个 Merge 的背景输入；同一源画面经主体 alpha/遮罩处理后，接到第二个 Merge 的前景输入。第二次 Merge 将人物与伞恢复到文字前面。
- 对静态图片可用 Polygon / B-Spline 细描轮廓；视频需要随时间变化的轮廓、可用的追踪/分割结果，并修正遮挡、形变与出入画。
- Text+ 可用竖排能力或逐字换行。Transform 的横坐标常是归一化值；目标速度为 `v` 像素/秒时，横向增量为 `v / 输出宽度` 每秒，而不是直接填入 275。
- 将光晕、柔化放在文字分支中。在共用源分支或最终合成上统一镜头变换，避免背景与抠像分支的裁切和缩放不同。
- 保存项目；如交付项目归档，实际检查媒体是否被收集以及用户能否重新打开。

## 导出与交接

1. 先在时间线上动态播放完整短片：同一列字在未循环的相邻时点必须更靠右；观察速度是否明显、是否有画内跳回。
2. 检查文字穿过人物时的头发、脸、手、衣袖、衣摆、脚与伞沿。至少查看首、中、尾以及快速运动、遮挡变化和镜头切换处；自动技术检查与抽帧不能代替完整动态观看。
3. 检查导出范围、分辨率、帧率和音频；避免把顶部抠像层的重复音轨一起导出。视觉 demo 可明确保持无声，不能把意外丢失原音说成设计选择。
4. 导出到新文件，重新检查实际导出文件的方向、遮罩同步、透明边缘和音轨。保存原生工程、媒体相对路径、字体依赖和外部透明层；不要只交一个无法追溯的 MP4。
5. 报告实际使用的软件、是否保留原生可编辑文字/仅可编辑透明视频层，以及完成的检查范围。只有在实际操控并保存之后，才称“已完成该软件工程”。
