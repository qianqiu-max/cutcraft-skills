# 从教程步骤到软件工程

## 选择软件和接口

用户指定软件优先；未指定时选择本机已经可运行、能覆盖核心效果的软件。先查询实际版本、公开接口或当前 UI，不凭历史记录宣称可用。优先稳定的原生 API/CLI；使用 GUI 时每次按观察→操作→回读验证，界面变化后重新定位控件，不硬编码教程画面中的点击坐标。

某个 MCP/插件连接失败只证明该接口当前不可用，不等于软件未安装。先检查同一软件已安装的可执行文件、独立 CLI 或 GUI 路径；有可靠替代接口便继续，并把原连接故障单独记录。不要为了恢复一个连接而自动改用户全局配置或接管正在编辑的工程。

按效果检查所需能力：

| 教程需求 | 应核实的能力 |
|---|---|
| 多层叠加/分屏 | 轨道合成、裁切、定位、透明通道 |
| 旋转/缩放/推拉转场 | 可设锚点、变换关键帧、插值曲线、运动模糊（若教程确有） |
| 人物抠像/遮挡 | 色键、蒙版、分割或转描；可检查边缘和遮挡关系 |
| 文字贴物/运动跟随 | 跟踪点或平面/相机跟踪，角度/透视匹配 |
| 调色/LUT | 色彩空间、LUT 输入要求、强度与可恢复调整层 |
| 卡点/字幕 | 音频波形、帧或时间级剪切、字幕时间与字体 |

缺一项不等于立即放弃：可用软件中等价图层/节点实现。缺专有效果时记录目标视觉特征，再决定是否能近似；不能把普通淡化命名为教程复杂转场。

## 建工程并保留可编辑性

- 明确时间单位：秒、帧号、源时间与成片时间分别记录；软件从0还是1开始计帧先核对。
- 保留媒体源和衍生副本。比例、帧率/时间基、色彩空间在项目开始确定；避免后期改帧率导致关键帧错位。
- 合理命名角色轨道，如主体、背景、遮罩、装饰、标题、配乐、音效。轨道编号高低以合成预览为准。
- 先确定主体位置与旋转中心，再动画；裁切/蒙版中心与变换锚点不同可能导致画面绕圈。方向角度在不同软件中不一定同号。
- 教程中多个图层组成整体转场时，用复合片段/嵌套时间线/节点组保持关系。若必须预渲染，同时保存分层源工程和总装工程，并说明哪些层已预渲染。
- 用户素材比教程多/少时按功能合并或延长镜头，保持效果节奏；不要为凑教程镜头数量替换用户主体。
- 文案、字幕、字体、滤镜和音效都需服务于教程效果。不要凭空给用户素材编造品牌、身份、参数或字幕内容。

## 最难片段先验证

选择能证实核心技法的时间区间，至少包含动作起点、过渡与落点。普通素材先粗剪不是充分验证：例如跟踪教程应先证明主体运动时文字能贴住，抠像教程应先证明边缘与前后遮挡，转场教程应先证明遮挡下切换不会露馅。

以实际导出或可靠合成预览查看，修正到可用后再铺开全片。此为内部自检，已有制作授权时不默认停下来等用户批准。用户明确要求先看样片时才等待其反馈。

## 导出与重新打开

保存工程后，使用该软件实际导出。队列提交、进程启动和返回路径均不等于导出成功；等待完成并检查文件。

重新打开原生工程，确认源媒体、蒙版、关键帧、音轨和复合片段还在。整理相对媒体路径或用软件打包；字体/插件不能分发时列出依赖与替代。必要时把整个包复制到独立目录验证媒体解析，避免只能在临时目录打开。

普通剪辑可输出 H.264 MP4；其他规格按用户要求和后续用途选定，不把某一次演示的720p/30fps变成强制标准。

没有可操作的软件时可准备素材、证据与编辑计划，但明确软件制作未完成。不能只交一份压平成片或伪造工程文件，就声称所有图层可编辑。
