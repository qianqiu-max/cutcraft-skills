# 对照教程检查与交付

在项目中保存 `validation.md`，按实际结果填写，不使用程序自动签署主观验收。

## 视觉与节奏对照

从制作计划选出决定“像教程”的3–8个特征，不固定套用同一张审美表。对每项写：教程证据位置 → 本片对应时间 → 相同/适配/近似/缺失 → 验证方式。

- 构图：主体所在区域、图层前后、留白、比例及文字安全区。
- 运动：方向、锚点、轨迹、速度、加减速、关键时刻、遮挡和落点；静态帧相似不能证明动作成立。
- 画面：蒙版/抠像边缘、跟踪稳定、颜色与亮度、透明叠加、是否把教程录屏UI烘焙到成片。
- 内容：用户人物/商品/事件仍是主体，未用网上素材替换关键内容，字幕/字卡不编造事实。
- 声音：对应教程的节奏、音量、卡点和转场声；无断词、突发空白、爆音或字幕不同步。静音示例明确标记。

合理适配不等于失败。不同素材导致的取景、动作速度、比例调整说明依据；如果放弃核心效果，则不能标“已复现”。

## 技术和工程检查

```text
ffprobe -v error -show_entries format=duration,size:stream=codec_type,codec_name,width,height,r_frame_rate,sample_rate,channels -of json <output.mp4>
ffmpeg -v error -i <output.mp4> -f null -
```

核对实际时长、尺寸、帧率、音轨、首尾以及完整解码。确认原生工程重新打开后媒体在线、图层/关键帧/蒙版仍存在，用户能继续修改。

字幕/口播需要逐句检查；自动识别、静音检测和波形属于辅助证据。带货项目另按当前适用规范检查宣传与商品一致性，不机械扩展到无关作品。

## 检查状态必须分开

| 检查 | 如实记录 |
|---|---|
| 教程理解覆盖 | 实际阅读/观看范围、是否仅抽帧/ASR、补读关键步骤、仍未确认参数 |
| 技术验证 | 命令/软件结果和实际输出，不只记“运行了命令” |
| 抽帧查看 | 具体区间与采样密度；未抽到问题不能声称所有帧无问题 |
| 完整动态观看 | 执行者、实际连续观看范围和结论；没做则待核验 |
| 完整听审 | 执行者、实际范围；没做则待核验，无音轨则不适用 |
| 授权 | 具体资源的许可依据、适用范围、署名或未核实项 |

记录失败原因、修复、复验与尚未解决事项。替代软件成功并不说明原软件故障已解决。对素材/工具的能力限制不夸大成所有平台都不支持。

## 交付

- 主成片与可播放预览。
- 原生工程及必要媒体；预渲染时保留分层源工程。
- 来源清单与简短的实现/差异/核验说明。
- 仅在任务需要时加封面、字幕、慢放、对比图。

输出包不包含浏览器Cookie、账户令牌、付费下载私链或无关私人文件。对外分享前按授权检查素材和本地路径信息。未明确授权不发布，不把本地交付或技术验证写成“发布前全验收通过”。
