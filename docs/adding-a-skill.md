# 把一个新效果收进 Cutcraft

## 先让效果能换素材跑起来

从教程中选定目标片段，记录时间码、图层顺序、运动方向、锚点、遮挡和声音。用自己的素材在合适的编辑引擎里做出一次，再换一组构图或色彩明显不同的输入检查。公开展示用自行制作或有相应授权的素材，文件中使用相对路径。

## 新建技能

在仓库根目录运行以下命令，标题和分类可替换。英文短名也用作提示词链接和页面地址，发布后尽量保持稳定。

```sh
python scripts/new_skill.py light-wipe --title "光线扫过转场" --category "转场" --engine "Blender"
```

```text
skills/light-wipe/
  SKILL.md             # 名称、适用条件、步骤、依赖、调用方式和验收
  showcase.json        # 页面显示信息及可复用提示词
  previews/poster.webp # 真实效果的清晰静帧，推荐横向 16:9
  previews/demo.mp4    # 可直接播放的公开示例，推荐 H.264、yuv420p、faststart
  scripts/             # 执行脚本放这里
  references/          # 需要时添加时间线、参数解释、视觉验收点
  assets/              # 可分发的字体替代说明、参数模板、几何资源等
```

`showcase.json` 中填写 `title`、`category`、`summary`、`engine`、`inputs`、`prompt` 和整数 `order`。`inputs` 是中文字符串数组。`featured` 可以指定首页特色效果，同时最多一个。`draft: true` 允许未做完的技能先提交，展示页和公开下载包只收录已完成并设为 `false` 的技能。公开 GitHub 仓库中的草稿文件对所有人可见。

## 写一段真正能复制使用的提示词

把目标效果、需要的附件、可自动决定的参数、最终文件和复核方式写入 `prompt`。直接使用本轮附件或用户选择的素材目录，普通用户不用先替换路径占位符。只在缺少必要输入时提问。构建脚本自动附上对应的完整技能包、原始说明和源码目录地址。

`SKILL.md` 需要 YAML 头的 `name` 和 `description`。`name` 与所在目录同名。脚本或文档引用的模板要随包提交。配乐、字体、模型、付费账号和插件的要求写明，不将开发者电脑上的绝对路径写成依赖。

## 验收与发布

1. 用两组素材运行，保存效果明确的预览。可编辑工程要重新打开并核对引用。分别记录已做的技术检测、抽帧、完整观看和听审。
2. 执行 `python -m unittest discover -s tests` 和 `python scripts/build.py`，本地启动站点。
3. 核对新卡片与分类、播放、提示词、源码和安装包。将 ZIP 解压到空目录，按说明检查脚本与资源能否找到。
4. 合并到 `main`，GitHub Pages 自动发布。用线上地址再次核对复制到的文本、样片以及 ZIP。需要撤下展示时可以改回草稿状态，保留源码与提交记录。
